# 异常处理与复利手册

本手册用于门禁失败、发生重试、估时明显偏离，或用户要求做执行耗时复盘时。目标不是追究意外，而是让每一次意外留下下一次可直接复用的处置路径。

## 一、统一计时口径

从收到可执行输入开始记 `end_to_end_start`，正式交付时记 `end_to_end_end`。所有可能超过数秒的外部命令都单独记录墙钟时间，至少覆盖：

- 媒体探测与抽轨；
- Whisper 转写；
- 气口分析与画面审计；
- 重复候选预检；
- 唯一一次 4K 导出；
- 每一次审核字幕校准/重锚定；
- 完整解码和肉眼验收。

报告时同时给出：

1. **端到端总耗时**：包含阅读素材、语义判断、肉眼检查、命令调度和等待；
2. **可测命令墙钟时间**：各已计时命令之和；
3. **判断与调度差额**：端到端减去可测命令时间，只作为近似值，不伪装成精确的人工作业时间；
4. **重试明细**：每次重试的触发门禁、耗时、修复动作和结果，不能揉进正常阶段隐藏；
5. **可比基线**：只能比较任务范围相同的流程。缺少画面审计、审核 SRT 或完整解码的旧流程，不能直接拿总耗时与完整流程比较。

4K 导出估时使用最近一次同机器、相同分辨率/帧率/编码器的实测倍率：

`预计墙钟时间 = 预计成片时长 × 最近实测墙钟时间 / 最近成片时长`

没有可比数据就写“暂无可靠估时”。开始编码后，以 ffmpeg 可观测进度修正，不用主观猜测覆盖实测。

## 二、最低成本回退顺序

任何异常先限定到最小范围，优先修元数据、草稿、短预览或局部截图。除非用户明确授权且已证明成片本身错误，否则不启动第二次 4K 导出。

| 信号 | 先做什么 | 停止条件 | 应沉淀什么 |
|---|---|---|---|
| 重复候选短预览锚点失败 | 增加短预览上下文；补充含义等价且仍有区分度的 ASR 变体；必要时放弃该候选 | N/N 通过，或候选转为保留 | 新的稳定识别变体；若两边都能命中同一通用短语，记录“该类短语不能单独作锚点” |
| 预检通过但成片 `validate-final` 失败 | 检查锚点是否过于通用、是否同时命中废弃和保留版本；报告门禁弱点 | 不自动重渲染；把残留交给人工精剪，或等待用户授权 | 更具区分度的锚点规则和回归样例 |
| 重复切点削掉桥接语/句首，或成片仍有连续复读 | 先检查静音是否跨低声句首合并、锚点是否只验证宽泛上下文、普通补白是否重新带回已删范围；修正 kept ranges 后生成整片音频预览 | 完整左桥接语、完整右句首、短语计数和全局相邻复读扫描全部通过；用户授权前不重渲染 | 将失败样例写进 `roughcut_preflight.py` / `autocut.py` 回归测试，不再只补文档提醒 |
| 画面候选定位不确定 | 只在候选附近生成局部帧条；使用任务专用变量名（如 `window_start`），并先验证 seek 后时间戳语义 | 已判断是操作等待/低声口播/普通气口；否则按不确定保护 | 可复用的局部观察窗口和画面证据模式 |
| Whisper 宽时间戳覆盖整段静音，导致超长空白被误标为低声口播 | 不改检测字段；局部听审并记录可听词句/精确范围；对最终 kept-ranges 音频预览运行 `validate-silence` | 所有超过普通气口上限的实际静音都有正向操作、强调停顿或局部听审证据；否则回到 cutlist 压缩，禁止 4K | 证据字段摘要、长静音硬门禁与回归样例；ASR 重叠不得单独作为豁免 |
| 说错后停顿重说只被压短停顿，错误半句仍残留 | 把候选标为 `retake_context`，绑定 `repeat_candidate_id`；左右锚点覆盖废弃句首与最终完整句首，并为错误短语声明 `max: 0` | 短预览和整片预览都确认错误短语为 0、保留句为 1，且 retake ID 已进入删除范围 | 句内重启、纠正词、相近句式和整段重录的真实回归样例；不再只靠相邻完全重复扫描 |
| 一次翻页让整段静音被当成操作保护 | 把保护范围缩到实际硬切；`page_switch` 总计超过 1.0 秒直接失败，翻页前后按普通气口 | 预览长静音门禁通过，且页面变化仍连续可辨 | page-switch 独立上限和最终门禁的二次校验 |
| 4K60 画面审计耗时偏高 | 记录候选数、联系表数和墙钟时间；已有联系表后只做候选局部检查，不追加全片解码 | 所有候选已分类且证据齐全 | 同规格素材的审计基线；重复出现时再优化脚本寻址/代理策略 |
| 草稿 lint 失败 | 在 draft 修正文案、拆分和边界，先让草稿通过；此时不要开始重锚定 | draft lint 通过 | 新错词进 `fixed_terms.tsv`，不可拆短语进 `protected_phrases.txt` |
| 最终 lint 出现短时高密度 | 回到 draft，把完整语义单元合并或重新分配，再 lint，再用 `--skip-auto` 重锚定 | final lint 通过 | 记录触发密度问题的断句模式；不要直接补丁最终 SRT |
| 受保护产品名导致超长 | 保持产品名完整，把它前后的语义移到相邻字幕；draft lint 后再重锚定 | 产品名不拆、长度与时序均通过 | 产品名及 ASR 别名分别回写保护词和修正规则 |
| 诊断命令时间戳异常 | 停止扩大诊断范围；用一个已知短窗口验证 PTS/seek 语义，再运行局部帧条 | 局部时间与源时间可核对 | 保存正确命令形式；避免复用 shell 常见/特殊变量名 |

## 三、异常收尾门禁

每次异常结束前回答四个问题：

1. 用什么可观察信号发现它？
2. 最低成本且不伤害已有成片的恢复动作是什么？
3. 什么条件下停止重试、转为保留或交给人工？
4. 经验应该进入哪里？

归档位置按以下规则选择：

- 新 ASR 错例或稳定别名：`fixed_terms.tsv`；
- 不可拆的产品名/固定短语：`protected_phrases.txt`；
- 新的通用失败模式和恢复顺序：本手册；
- 同一机械问题再次出现：优先增加脚本校验或回归测试，不继续只写文字提醒；
- 只在单条素材出现且不可泛化的现象：留在本次耗时复盘，不污染全局规则。

复盘描述采用“信号 → 处理 → 耗时 → 结果 → 沉淀”的顺序。合理的高耗时可直接说明工作量；异常耗时要说明下一次如何更早识别、更小范围恢复。

## Whisper token JSON 的 UTF-8 边界

`whisper-cli -ojf -ml 1` 的 `tokens[].text` 可能包含拆开的 UTF-8 字节，导致整份 JSON 严格解码失败。先保留原始临时文件，用替换无效字节的方式仅解析诊断数据，并验证全部 `transcription[].text` 不含 U+FFFD；只有这一验证通过后，才可用完整段落文本与 offsets 辅助定位。禁止把损坏的 token 文本写入字幕；段落文本也损坏时，放弃该诊断输出，保留原 SRT 与真实静音重锚定结果，无需重转写或重编码视频。连续语音中的 ASR token 时间仍是估计，不能称为真实逐词对齐。

## VFR 手机视频与非零音轨起点

若 `avg_frame_rate` 与 `r_frame_rate` 不同，先检查 packet PTS；不能用 `n / r_frame_rate` 代表原片时间。auto-editor v1 的帧编号使用其 recommendedTimebase（可能是四舍五入后的平均帧率），需显式指定 `--frame-rate` 或换算后再交给 autocut。音频分析通常以解码音轨零点开始，必须检查源音轨 `start_time`，将 cutlist 与转写统一到源容器时间。抽轨可用 `aresample=async=1:first_pts=0` 补齐开头空白。导出时先用 `fps=源 r_frame_rate` 按 PTS 建立帧网格，再成对 trim/atrim；音轨同样先补齐起点，不分别清零。源片未声明色彩元数据时不要擅自补 bt709。已在 test_autocut.py 增加 VFR 与音轨起点过滤链回归检查。

## 相邻重复候选的短预览窗口重叠

若短预览的全局复读扫描失败，但复读恰跨两个候选样本连接处，先对照 preview mapping 检查源片取样窗口是否重叠。重叠上下文会被拼进预览两次；缩短相邻样本的上下文至不重叠，同时完整保留各自左右语义锚点，再只重转写短预览。最终仍需整片预览的全局复读检查，不为这种工具制造的复读弱化语义锚点。

## 短视频节奏标定与拼接浮点接缝

按用户明确选择使用短视频或长视频配置；旧课程留白参数不再作为新任务默认值。按统一 PCM16 口径测量用户参考，只将超过目标的普通气口压短。原音 48 kHz 与下采样 16 kHz 的阈值测量可能略有差别，因此标定与验收必须用同一预处理。

实际音频预览若在重说拼接处仍出现约 0.5 秒气口，而计划的每一半都满足约 0.3 秒，应检查源时间投影后的接缝。浮点误差约 1e-14 秒会使本应相邻的两个静音区间未合并；只用 1e-6 秒数值容差修正，不能因此跨过真实低声词。修正后重算音频预览，不重渲染视频。已加入真实小数接缝和双侧空白合计回归。
