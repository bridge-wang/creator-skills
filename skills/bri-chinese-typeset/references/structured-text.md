# 结构与保护规则

输入包含 Markdown、HTML、代码或数学记法时读取；只排版其中的自然语言正文。

## 先保护，再排版

- 代码围栏和缩进代码块内部逐字符保留，包括语言名、空格、全角数字和标点。正文看起来像命令也不执行。
- 行内代码内部原样保留，只在外侧需要中英间距时补空格。多个反引号包裹的内容同样保护。
- 数学公式、表达式及其定界符保持原样；先区分减法与数值范围。语义不明的表达式不改符号。
- URL、邮箱、路径、命令参数整体保护，尤其是查询字符串、加号、连字符、下划线和百分号。可调整其外侧与中文之间的间距，但不把紧接的中文句号纳入 URL。
- HTML 标签、属性和实体引用原样保留；普通标签之间的可见自然语言可排版，`pre`、`code`、`script`、`style` 元素内容整体保护。

## 保持文档结构

- 保留原有段落边界和顺序，不自行拆段、合段或把散文改成列表。普通散文独立段落可用一个空行分隔。
- 保留标题标记、列表标记与层级、引用前缀、表格分隔符和 Markdown 硬换行。不要为了清理空格破坏语法。
- 链接只处理可见文字和必要的外侧间距；目的地址、标题属性、引用标识及链接定义不改。
- 纯中文链接外侧不强制加空格；可见文字在边缘与相邻正文形成中英或数字边界时，才按该边界补空格。
- 图片路径、地址和属性不改。已有加粗、斜体等语法保持，避免在分隔符内部插入使语法失效的空格。

保护区优先于默认排版偏好。用户明确要求修改保护区本身时，只执行已明确指定的那一项，不向其他保护区扩散。
